# 规则改进记录

这里评估的是**虚构文本的归档建议**，不是候选人的能力、录用概率或真实招聘准确率。

## 数据隔离

- 首页 10 条虚构样本用于演示和功能回归。
- `dist/development-data.mjs` 的 25 条虚构样本用于设计与验证改进规则，覆盖技术别名、跨岗位经历、否定描述、学习意向和弱证据。
- `dist/benchmark-data.mjs` 原有的 40 条挑战样本保持不变。先在开发样本上完成规则修改，再用挑战集复测。挑战集不用于继续调整规则。
- `dist/baseline-classifier.mjs` 保存改进前的关键词计数实现，确保旧结果可以重新计算；新规则位于 `dist/classifier.mjs`。

## 修改内容

1. 为四类岗位补充常见技术别名。用户仍可在页面编辑关键词。
2. 根据句段中的“主要 / 负责”和“偶尔 / 曾经 / 培训练习”等描述，区分主要经历与辅助经历。
3. 排除含有“不熟悉 / 尚未 / 学习计划”等表达的句段。目标岗位尚未确定时，交给人工复核。
4. 证据不足或两个岗位线索接近时，仍不给出自动岗位建议。所有建议都需要人工确认。

这些是有限的确定性规则。它们不能可靠理解任意措辞、推断真实经历或评估人选，也不能替代招聘人员。

## 固定挑战集复测

| 指标 | 原始规则 | 改进规则 |
| --- | ---: | ---: |
| 与预设标签完全一致 | 22/40（55%） | 37/40（92.5%） |
| 自动建议覆盖 | 21/40（52.5%） | 31/40（77.5%） |
| 自动建议中正确 | 17/21（约 81.0%） | 30/31（约 96.8%） |
| 错误的自动建议 | 4 | 1 |
| 应复核案例中进入复核 | 5/8（62.5%） | 7/8（87.5%） |

开发样本上，原始规则为 11/25，改进规则为 25/25。开发样本结果只说明规则覆盖了设计时考虑的措辞，不能当作泛化效果。

改进规则在挑战集仍有 3 个不一致案例：B07（后端经历被交给人工）、A04（AI 经历被交给人工）、R06（协调工作中的 SQL/Pandas 清单被误判为数据分析）。其中 R06 是错误的自动建议，属于需要优先处理的风险。页面“离线评测”保留了这些逐条错误及混淆矩阵。

## 复现

```powershell
npm test
npm run test:e2e
```

两个命令都只使用本地规则与虚构数据，不调用 OpenAI API。
